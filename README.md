# Отчёт «аванс по договору»

Программа читает выгрузку из учёта (`contracts.csv`, `works.csv`, `payments.csv`) и строит
отчёт на заданную дату: по каждой работе — цена, сколько выплачено и сколько осталось
оплатить; по каждому договору — итоги. Деньги считаются в `Decimal` до копейки.

Никаких внешних зависимостей: только стандартная библиотека Python.

---

## Как запустить

Нужен Python 3.10+ (проверено на 3.14). Из папки `solution`:

```bash
# отчёт на 10.11.2026 в консоль
python report.py --date 2026-11-10

# все файлы отчёта в папку out
python report.py --date 2026-11-10 --format all --out out

# конкретный формат
python report.py --date 2026-11-10 --format md  --out out
python report.py --date 2026-11-10 --format csv --out out
python report.py --date 2026-11-10 --format json --out out

# другая папка с выгрузкой
python report.py --data ..\data --date 2026-11-10
```

Если `--date` не указать, берётся сегодняшняя дата; для воспроизводимости её лучше указывать
явно. По умолчанию данные берутся из `../data` относительно папки решения. Самой выгрузки
`data/` в репозитории нет — если её нет рядом с папкой решения, передайте путь через `--data`.

### Параметры

| Параметр | Что делает |
|---|---|
| `--data DIR` | каталог с тремя CSV (по умолчанию `../data`) |
| `--date`, `--as-of ГГГГ-ММ-ДД` | отчётная дата, день включительно |
| `--format console\|md\|csv\|json\|all` | куда выводить (по умолчанию `console`) |
| `--out DIR` | каталог для файлов (по умолчанию `out`) |
| `--csv-delimiter` | разделитель CSV, по умолчанию `;` (так открывает Excel) |
| `--csv-dot` | писать в CSV точку вместо запятой в дробях |

### Коды возврата

| Код | Значение |
|---|---|
| `0` | отчёт построен (предупреждения не мешают) |
| `2` | данные противоречат формату — отчёт не строился (в сообщении файл, строка, колонка) |
| `3` | нарушен внутренний инвариант расчёта (дефект программы) |
| `4` | не удалось записать файлы |

## Что получается

`--format all` пишет в `out/`:

| Файл | Для чего |
|---|---|
| `report_2026-11-10.md` | читаемый отчёт: таблицы работ и договоров, платежи, сверки |
| `works_2026-11-10.csv` | работы: цена, выплачено (прямое / из платежей), остаток, источники |
| `contracts_2026-11-10.csv` | договоры: сумма, отменено, к оплате, выплачено, остаток, переплата, очередь |
| `payments_2026-11-10.csv` | все платежи с пометкой «учтён / не учтён» и причиной |
| `report_2026-11-10.json` | тот же отчёт для машинной обработки, деньги строками |

Готовый отчёт на 10.11.2026 уже лежит в [`out/`](out/report_2026-11-10.md).

## Как читать отчёт

* **Выплачено** — деньги, которые ушли подрядчику и на отчётную дату не вернулись.
  Возвраты (P-2) и платежи в очереди (P-4) сюда не входят; платежи позже отчётной даты
  (P-8) тоже не входят и вынесены в блок «События после отчётной даты».
* **Осталось оплатить** = «к оплате» − «выплачено». «К оплате» — сумма цен работ минус
  отменённые работы.
* **Аванс сверх принятого** — сколько денег ушло вперёд приёмки: по принятым работам долга нет,
  весь остаток относится к работам, которых на дату ещё не приняли.
* **Источники выплат** — из каких платежей сложилась сумма по работе. Непривязанные платежи
  разложены по порядку приёмки (ФИФО), прямые (`work_id`) идут в свою работу.

Подробно все допущения — в [DECISIONS.md](DECISIONS.md), коротко для бухгалтера —
в [NOTES_TO_ACCOUNTANT.md](NOTES_TO_ACCOUNTANT.md).

## Тесты

```bash
python -m unittest discover -s tests -v
```

83 теста: разбор сумм и дат, проверки загрузки (битые статусы, чужие ссылки, возвраты),
расчёт на реальной выгрузке с эталонными цифрами, граничные случаи (переплата, пустой
договор, копейки), CLI (коды возврата, форматы, побайтовая повторяемость).

Ключевой тест — `tests/test_engine.py::RealDataTests`: цифры на 10.11.2026 посчитаны вручную
по строкам CSV и служат эталоном.

## Ограничения

* Одна валюта (рубли), НДС не выделяется — в выгрузке нет ни ставки, ни признака.
* Частичные акты и авансовые счёта не моделируются: формат их не содержит.
* Данные, противоречащие формату, не «чинятся»: программа останавливается с понятным
  сообщением, чтобы не выдать неверную цифру.
* Распределение непривязанных платежей — допущение (ФИФО по дате приёмки), его стоит
  подтвердить у бухгалтера; в коде это одно место (`engine._allocate`) и меняется отдельно.
